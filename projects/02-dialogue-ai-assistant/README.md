# Dialogue AI Assistant

Учебный проект по теме **Google AI Studio: Designing a Dialogue AI Assistant**.

Проект одновременно решает требования **ДЗ 2236 PRO** и формирует первый прикладной модуль будущей универсальной платформы AI-агентов.

## Задача ДЗ 2236 PRO

Необходимо собрать рабочее веб-приложение, которое:

- ведёт диалог пользователя с AI-ассистентом;
- автоматически формирует структурированную информацию о пользователе в конце диалога;
- запускает отдельный аналитический промпт или отдельную модель по полной истории беседы;
- формирует итоговое резюме и персональные рекомендации;
- создаёт брендированный PDF с логотипом, датой и структурой;
- предоставляет PDF для скачивания.

## Главное архитектурное решение

Диалоговая и аналитическая задачи разделяются.

```text
Пользователь
    │
    ▼
Web UI
    │
    ▼
Django API
    │
    ├── Dialogue Model
    │      └── ведёт беседу и задаёт вопросы
    │
    ├── Conversation Storage
    │      └── сохраняет полную историю
    │
    └── Analysis Model
           ├── анализирует весь диалог
           ├── формирует структурированный JSON
           ├── пишет резюме и рекомендации
           └── передаёт результат PDF Generator
                         │
                         ▼
                  Branded PDF
```

Первая модель не должна самостоятельно окончательно оценивать пользователя. Вторая модель получает полную историю разговора и выполняет отдельную аналитическую задачу.

## Функциональный сценарий

1. Пользователь открывает веб-страницу.
2. Система создаёт новую сессию диалога.
3. Пользователь и AI-ассистент обмениваются сообщениями.
4. Все сообщения сохраняются в базе данных.
5. Пользователь нажимает кнопку **«Завершить диалог»**.
6. Backend блокирует дальнейшее изменение завершённой сессии.
7. Отдельный аналитический сервис получает всю историю.
8. Модель возвращает структурированный результат.
9. Результат проверяется схемой данных.
10. Генератор создаёт PDF по брендированному HTML-шаблону.
11. Пользователь скачивает готовый файл.

## Структура аналитического результата

Пример ожидаемой схемы:

```json
{
  "profile": {
    "name": "Имя или null",
    "goals": ["Цель 1", "Цель 2"],
    "experience": "Краткое описание опыта",
    "interests": ["Интерес 1"],
    "constraints": ["Ограничение 1"]
  },
  "summary": "Итоговое аналитическое резюме",
  "recommendations": [
    {
      "title": "Рекомендация",
      "reason": "Почему она предложена",
      "next_step": "Следующее действие"
    }
  ],
  "confidence": 0.85,
  "missing_information": ["Каких данных не хватило"],
  "disclaimer": "Выводы сформированы на основе диалога и могут требовать уточнения."
}
```

## Требования к PDF

PDF должен содержать:

- логотип проекта;
- название отчёта;
- уникальный номер отчёта;
- дату и время создания;
- краткие сведения о пользователе;
- цели и интересы;
- аналитическое резюме;
- персональные рекомендации;
- ограничения анализа;
- служебный footer с названием проекта.

PDF нельзя формировать прямой подстановкой отдельных полей из формы. Основной содержательный текст обязан поступать из результата второй аналитической модели.

## API первой версии

```text
POST /api/v1/conversations/                  создать диалог
GET  /api/v1/conversations/{id}/             получить состояние
POST /api/v1/conversations/{id}/messages/    отправить сообщение
POST /api/v1/conversations/{id}/complete/    завершить и запустить анализ
GET  /api/v1/conversations/{id}/analysis/    получить аналитику
GET  /api/v1/conversations/{id}/report/      скачать PDF
GET  /api/v1/health/                         проверка работоспособности
```

## Модели данных

```text
Conversation
├── id
├── public_id
├── status
├── started_at
├── completed_at
└── created_by / session_key

Message
├── conversation
├── role: user | assistant | system
├── content
├── created_at
└── sequence_number

UserAnalysis
├── conversation
├── structured_data
├── summary
├── recommendations
├── confidence
├── model_name
└── created_at

GeneratedReport
├── conversation
├── file
├── checksum
├── template_version
└── created_at
```

## Статусы диалога

```text
NEW → ACTIVE → ANALYZING → COMPLETED
                    └────→ FAILED
```

Повторное завершение должно быть идемпотентным: оно не создаёт второй анализ и второй PDF без явного запроса на регенерацию.

```bash

copy .env.example .env
python manage.py migrate
python manage.py runserver
```

Никогда не добавляйте настоящий API-ключ в Git.
