# MONGOOSE AI PLATFORM — Design System

## 1. Статус документа

- Версия: `v0.2.0-draft`
- Статус: Approved baseline
- Область: Web Portal, Admin Center, Dialogue Center, CRM, Knowledge Factory, Security Center и специализированные агенты
- Ветка внедрения: `integration/mongoose-platform-v0.1`

## 2. Главный визуальный принцип

MONGOOSE AI PLATFORM должна выглядеть как премиальный корпоративный AI-продукт, даже если отдельные модули пока реализованы только в формате MVP.

Архитектура интерфейса создаётся один раз. При добавлении нового учебного задания, агента или отраслевого модуля меняются:

- hero-изображение;
- заголовок и описание;
- активный раздел;
- набор карточек;
- тематические акценты;
- содержимое рабочего экрана.

Не меняются:

- базовый шаблон;
- сетка;
- навигация;
- типографика;
- кнопки;
- формы;
- анимации;
- правила доступности;
- фирменная идентичность.

## 3. Визуальная модель

Стиль платформы:

- enterprise premium;
- современный минимализм;
- тёмный графитовый фон;
- холодные синие и изумрудные акценты;
- мягкие градиенты;
- glass-effect без потери читаемости;
- умеренное свечение;
- плавная глубина и слои;
- чистые поверхности без визуального шума.

Интерфейс не должен выглядеть как учебная страница, стандартная Django Admin или набор Bootstrap-компонентов без кастомизации.

## 4. Брендинг

Обязательные элементы:

```text
static/branding/
├── favicon.svg
├── favicon.ico
├── logo.svg
├── logo-mark.svg
└── wordmark.svg
```

Во вкладке браузера обязательно отображаются:

- фирменный favicon;
- короткое название текущего раздела;
- бренд `MONGOOSE AI`.

Пример:

```text
Dialogue Center — MONGOOSE AI
Security Center — MONGOOSE AI
Travel Agent — MONGOOSE AI
```

:root {

## 6. Типографика

Требования:

- крупные, короткие заголовки;
- читаемый основной текст;
- заметная визуальная иерархия;
- достаточное межстрочное расстояние;
- отсутствие чрезмерно мелкого текста;
- ограниченная длина строк в текстовых блоках.

Приоритет:

1. локальный системный стек;
2. безопасно подключаемый web-font;
3. fallback sans-serif.

## 7. Кнопки

### 7.1. Состояние по умолчанию

- чёткий контраст;
- мягкий градиент;
- скругление;
- лёгкая внутренняя подсветка;
- заметный фокус с клавиатуры.

### 7.2. Наведение

При наведении кнопка должна:

- слегка подниматься;
- усиливать свечение;
- показывать переливающийся блик;
- плавно менять интенсивность градиента;
- не дёргаться и не менять размер макета.

Рекомендуемый эффект:

```css
.button {
    position: relative;
    overflow: hidden;
    transition:
        transform var(--transition-fast),
        box-shadow var(--transition-base),
        filter var(--transition-base);
}

.button::before {
    content: "";
    position: absolute;
    inset: 0;
    transform: translateX(-130%) skewX(-18deg);
    background: linear-gradient(
        90deg,
        transparent,
        rgba(255, 255, 255, 0.26),
        transparent
    );
    transition: transform 520ms ease;
}

.button:hover {
    transform: translateY(-2px);
    box-shadow: var(--shadow-glow);
    filter: brightness(1.08);
}

.button:hover::before {
    transform: translateX(130%) skewX(-18deg);
}
```

### 7.3. Нажатие

При нажатии кнопка должна:

- опускаться на 1–2 px;
- временно менять яркость;
- менять направление или интенсивность света;
- создавать ощущение физического нажатия;
- сохранять доступность текста.

```css
.button:active {
    transform: translateY(1px) scale(0.985);
    filter: brightness(0.92);
    box-shadow: 0 0 18px rgba(56, 189, 248, 0.18);
}
```

### 7.4. Состояния

Обязательные состояния:

- default;
- hover;
- active;
- focus-visible;
- disabled;
- loading;
- success;
- danger.

## 8. Карточки

Карточки разделов и объектов должны:

- иметь единый радиус;
- использовать прозрачную границу;
- иметь мягкую тень;
- подниматься на 3–5 px при наведении;
- усиливать рамку и внутреннее свечение;
- не использовать резкие анимации.

## 9. Навигация

### Верхняя панель

Содержит:

- логотип;
- название платформы;
- основные разделы;
- профиль пользователя;
- состояние системы;
- переключатель темы в будущем.

### Боковое меню

Активный пункт:

- имеет светящуюся вертикальную полосу;
- меняет цвет текста и иконки;
- получает мягкий фон;
- остаётся различимым без одного только цвета.

## 10. Hero-блоки и смена изображений

Каждый модуль получает собственный визуальный профиль.

Пример сопоставления:

| Раздел | Визуальная тема |
|---|---|
| Главная | premium AI / enterprise platform |
| Dialogue Center | intelligent communication |
| CRM | clients and business relations |
| Knowledge Factory | documents, graph, RAG |
| Security Center | cyber operations center |
| OSINT | investigation, maps, open sources |
| Reports | analytics and dashboards |
| Travel Agent | destinations and route planning |
| Hotel Agent | premium hospitality |
| HR Agent | people and recruitment |
| Legal Agent | law and structured documents |
| Education Agent | learning and knowledge |

Все изображения должны:

- быть юридически допустимыми для использования;
- храниться локально или подключаться через контролируемый источник;
- иметь оптимизированный формат, предпочтительно WebP/AVIF;
- иметь альтернативный текст;
- не ухудшать контраст текста;
- загружаться лениво вне первого экрана.

## 11. Чат

Чат должен включать:

- отдельные стили сообщений пользователя и AI;
- фирменный знак AI;
- анимацию ожидания;
- понятный статус ошибки;
- безопасный вывод через `textContent` или экранированные шаблоны;
- адаптивную форму;
- заметную кнопку отправки;
- поддержку длинных сообщений;
- доступное управление с клавиатуры.

## 12. Формы

Формы должны иметь:

- явные label;
- состояния focus, error, success, disabled;
- подсказки без подмены label placeholder-ом;
- визуально понятные ошибки;
- единое расположение элементов;
- серверную и клиентскую валидацию;
- отсутствие небезопасного HTML в сообщениях ошибок.

## 13. Таблицы и CRM

Таблицы должны:

- поддерживать hover строки;
- не терять читаемость на тёмном фоне;
- использовать фиксированную визуальную иерархию;
- адаптироваться к узкому экрану;
- иметь понятные статусы;
- поддерживать будущие сортировку и фильтрацию.

## 14. Анимации

Базовая длительность:

- быстрые реакции: 120–180 ms;
- стандартные переходы: 180–260 ms;
- крупные появления: до 420 ms.

Запрещено:

- постоянное раздражающее мерцание;
- резкие скачки;
- чрезмерное движение;
- анимации, блокирующие работу;
- зависимость смысла только от анимации.

Обязательно учитывать `prefers-reduced-motion`.

## 15. Иконки

Используется один согласованный набор, например Lucide.

Правила:

- одинаковая толщина линий;
- единый размер внутри одного уровня интерфейса;
- иконка не заменяет текст там, где смысл может быть неочевиден;
- внешние библиотеки не должны подключаться без фиксации версии.

## 16. Адаптивность

Минимальные целевые режимы:

- desktop;
- tablet;
- mobile.

Мобильная версия создаётся одновременно с компонентом, а не отдельным будущим проектом.

## 17. Доступность

Минимальный baseline:

- достаточный контраст;
- видимый `focus-visible`;
- управление клавиатурой;
- корректная семантика HTML;
- `aria-*` только там, где это необходимо;
- alt-тексты изображений;
- поддержка уменьшенного движения;
- отсутствие информации, передаваемой только цветом.

## 18. Безопасность визуального слоя

- никаких секретов в JavaScript;
- никакого `innerHTML` для пользовательского или AI-контента;
- CSP-ready архитектура;
- локальные или контролируемые зависимости;
- фиксация версий библиотек;
- безопасная обработка загружаемых изображений;
- запрет inline-скриптов в production-профиле;
- отсутствие внешних трекеров без явного решения.

## 20. Версионирование

Первый визуальный релиз:

```text
v0.2.0 — Premium Web Shell
```

Состав релиза:

- favicon;
- фирменный логотип;
- `base.html`;
- общая навигация;
- премиальная главная;
- премиальный чат;
- кнопки с переливом;
- световая реакция при нажатии;
- карточки и hero-блоки;
- адаптивность;
- базовая доступность;
- смена изображений по модулю.

## 21. Definition of Done для нового экрана

Экран считается готовым, если:

- использует `base.html`;
- использует фирменные токены;
- имеет favicon и корректный title;
- адаптируется под мобильный экран;
- имеет hover/active/focus состояния;
- не содержит небезопасного вывода;
- поддерживает уменьшение анимации;
- соответствует тематическому профилю модуля;
- не ломает работающий API;
- проходит минимальную ручную проверку в браузере.

## 22. Итоговый принцип

> Один раз создаём премиальный фирменный интерфейс MONGOOSE AI PLATFORM. Каждый новый учебный модуль, агент или отраслевое задание получает собственные изображения и контент, но использует ту же дизайн-систему, компоненты, безопасность и навигацию.
