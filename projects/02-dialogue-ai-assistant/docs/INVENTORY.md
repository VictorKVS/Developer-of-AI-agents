# INVENTORY — MONGOOSE AI PLATFORM

## 1. Цель

Зафиксировать фактическое состояние веток перед объединением. Этот документ отделяет реально реализованные компоненты от запланированных и предотвращает повторную разработку уже работающих модулей.

## 2. Проверенные ветки

- `feature/2236-pro-dialogue-assistant` — текущая рабочая версия учебного проекта и основа платформы.
- `rebuild/mongoose-ai-platform` — ранний чистый каркас платформы в каталоге `platform/`.
- `integration/mongoose-platform-v0.1` — интеграционная ветка, созданная от текущей рабочей версии.

Сравнение показало, что ветки разошлись от общего начального коммита. Ветка `rebuild/mongoose-ai-platform` содержит 21 собственный коммит, но отстаёт от рабочей ветки на 83 коммита.

## 3. Что реально есть в `feature/2236-pro-dialogue-assistant`

- Django 5 и Django REST Framework;
- Python 3.10;
- модели диалогов и сообщений;
- REST API создания и чтения диалогов;
- endpoint `/chat/`;
- общий слой `mongoose_core`;
- LLM-порты и провайдеры;
- рабочая интеграция GigaChat;
- заготовка Gemini;
- анализ диалога;
- модели и шаблоны отчётов;
- WeasyPrint в зависимостях;
- Web Portal;
- рабочий веб-чат;
- CSRF-защита;
- request tracing и correlation ID;
- журналы приложения, ошибок и событий безопасности;
- миграции БД;
- тестовая инфраструктура pytest;
- архитектурная документация;
- стандарт будущего агента;
- план объединения платформы.

### Проверено вручную

- Django запускается локально;
- health endpoint работает;
- создание диалога работает;
- GigaChat отвечает;
- русский текст корректно хранится в БД;
- веб-чат выполняет полный цикл Browser → API → GigaChat → Browser.

## 4. Что реально есть в `rebuild/mongoose-ai-platform`

Ветка содержит отдельный минимальный проект в каталоге `platform/`:

- Django 5;
- REST API;
- модели `Conversation` и `Message`;
- serializers/views/urls для диалогов;
- простой `mongoose_core/llm.py`;
- протокол `LLMProvider`;
- `GigaChatProvider`;
- SQLite;
- `.env.example`;
- минимальный README;
- Python 3.10.

## 6. Что переносим из rebuild

Прямой перенос кода почти не требуется. Полезны только идеи:

1. Короткий и ясный README платформы.
2. Акцент на Python 3.10 как корпоративной совместимой версии.
3. Единая формулировка: каждый учебный проект расширяет одну платформу.
4. Возможная будущая реорганизация корня в каталог `platform/` после сдачи ДЗ 2236.

## 7. Что не переносим

- не переносим второй Django-проект целиком;
- не дублируем `Conversation` и `Message`;
- не заменяем текущий `mongoose_core` упрощённым `llm.py`;
- не переносим отдельные settings/urls/manage.py;
- не делаем merge ветки `rebuild` целиком;
- не меняем рабочую структуру до завершения текущего ДЗ.

Причина: это создаст дублирование моделей, миграций, настроек, API и LLM-слоёв.

## 8. Решение по основной архитектуре

Технической основой `MONGOOSE AI PLATFORM v0.1` становится:

`feature/2236-pro-dialogue-assistant` → `integration/mongoose-platform-v0.1`

Ветка `rebuild/mongoose-ai-platform` сохраняется как исторический архитектурный прототип и источник отдельных идей, но не как источник полного merge.
